# Runtime build helpers

[build-windows-app.mjs](build-windows-app.mjs) builds a local unsigned x64 NSIS engineering installer from an explicitly selected pinned runtime and reviewed file inventory. It refuses existing or linked outputs, mismatched bytes/architecture/pin and installed PostgreSQL state. It preserves the manifest's existing resources, disables publishing and signing, and retains build/resource/checksum receipts. The installer selects per-user installation, leaves profile data on uninstall and does not start the app after assembly. These are configuration and payload checks; [actual build and extraction proof](../docs/cycles/evidence/C106/installer-02/README.md) does not establish installed-machine behavior, prerequisite closure or A5 acceptance.

The Windows reader builder in [runtime-wasm-assets.mjs](runtime-wasm-assets.mjs) archives the pinned Barkpark source, requires its Go version, builds into a new owned directory, checks gzip/loader identity and runs the upstream reader smoke tests. It retains source and compiler hashes in its report. Existing output refuses rather than being overwritten.

Go VCS stamping is disabled because the archive has no repository metadata: otherwise Go can record the surrounding Barkdown checkout. [Two-parent build proof](../docs/cycles/evidence/C098/reader-vcs-repair-review.md) compares complete WASM/gzip/loader hashes and reproduces the old defect with a control build. This repairs future reader builds; the previously tested carried runtime remains unchanged.

[build-runtime-release-windows.mjs](build-runtime-release-windows.mjs) consumes these assets when assembling a fresh Windows release. Full notices, prerequisites and ordinary installation remain separate gates in [C098](../docs/cycles/C098-windows-packaging.md).

The offline runtime auditor binds all three measured Paper assets, six fonts and both player assets through `frontend-notices.mjs`. Before source-bound checks, ensure generated code uses LF and compare staged owner bytes to the tested bytes. A trailing newline normalized only by Git can invalidate a raw source receipt even when JavaScript behavior is unchanged.

[windows-sandbox-baseline.mjs](windows-sandbox-baseline.mjs) prepares a baseline-only .wsb configuration in a new absolute local folder. It maps only its collector read-only and its new output writable, disables network/clipboard/device sharing and never launches a guest. Existing output, junction ancestors, environment macros and overlapping maps refuse. [Native host and configuration review](../docs/cycles/evidence/C098/baseline-review.md) verifies the collector, typed CRT contract and output preservation; guest execution remains unproven.

The read-only collector records selected OS/virtualization/feature fields, both explicit CRT registry views, fixed system-file hashes/signatures and executable presence on PATH. It does not execute discovered tools or decide a supported minimum. The role is a caller label, never clean-machine proof. This host currently has Sandbox disabled and Hyper-V enabled; feature activation, guest media and effective guest policies require a separate checkpoint.

For local Hyper-V preflight, discover the actual versioned native module before declaring it unavailable and target the local computer explicitly. A sparse child environment can produce ArgumentNullException before authorization is evaluated; preserve structured diagnostics and use a fixed metadata whitelist. [Guest availability review](../docs/cycles/evidence/C098/guest-review.md) records the original probes and final permission denial. Empty filtered provider responses do not establish that no guests/images exist, and a module import does not authorize operating a guest.

For native PTY lifecycle review, trace configurable backends invoked through apply/3 as well as direct API references. Check explicit child PID absence before measuring the surviving host; sample again after all wrapper stops. [Carried resource review](../docs/cycles/evidence/C098/pty-resources-review.md) keeps callback, OS exit, wrapper stop and host cleanup as distinct observations. CPU ticks divided by monotonic elapsed time are logical-processor equivalents, not whole-machine usage or allocation attribution.

The [isolated ExPTY prototype](../docs/cycles/evidence/C098/pty-lifecycle-review.md) retains actual Release/BEAM compiler inputs and failure probes without adopting them into the runtime. Compile fixture helpers before expensive native launch: AST parsing alone misses macro errors. Verify boot-preloaded module identity, physical file identity for canonical/8.3 paths and actual JSON atom serialization. Mark skipped closed-API calls false when the wrapper is already dead; keep OS absence, callback and native cleanup evidence distinct.

[Fresh packaged ExPTY candidate](../docs/cycles/evidence/C098/pty-package-review.md) keeps complete runtime byte identity and relevant source/license copies separate from app acceptance. Prove the actual packaged native binding and real Electron save/restart/recovery before broad capture. An asynchronous module observation can race normal quit; retain that failure and do not infer a loaded module. Full standard captures stay separate from actual packaged Paper/reader evidence.

## Media observations

[media-ownership-observations.mjs](media-ownership-observations.mjs) compares explicitly supplied raw row/file observations. [report-media-observations.mjs](report-media-observations.mjs) reads one bounded JSON input and creates one new absolute output path; existing output refuses. It operates on the observation files only. The report preserves stored physical keys, raw scope, null-key fallback, unclaimed/unobserved/absent/uncertain files and potential aliases, always partial and without recovery/deletion authority. [Actual observations and refusal proof](../docs/cycles/evidence/C101/review.md) retain the input format. A trusted full database/filesystem/exclusion collector and durable media repair are not implemented.

Run `node scripts/report-media-observations.mjs <absolute-input.json> <new-absolute-output.json>`. Do not label targeted/public metadata or a current hash as complete ownership, historical intent or authenticity. Unknown/malformed/unsafe values, invalid UTF8 and exhausted bounds refuse before output. Region ownership is checked before absence; cache/unknown absence cannot assert missing originals. Unrelated raw row columns are not echoed into reports.

Before a new observation parser reaches broad verification, review region ownership and lossless decoding against raw inputs and run explicit refusal cases. A helper default can hide an intentionally absent field; construct that value explicitly. C101 retains the original fixture and semantic regressions rather than treating its earlier root passes as final-source proof.

[media-row-snapshot.mjs](media-row-snapshot.mjs) builds static schema-qualified SQL for one repeatable-read, read-only transaction and interprets its raw rows, schema/count, opaque directory bytes, transaction identity and UTF8 declarations. It pins client encoding; callers must independently bind the actual owned cluster, enforce stable exclusion and decode transport with fatal UTF8. No arbitrary SQL endpoint or connection owner is added. Exhausted bounds retain an explicit incomplete prefix. Even completeRows is database rows only, never a complete filesystem inventory or recovery authority. [Actual Windows proof](../docs/cycles/evidence/C102/review.md) distinguishes three API originals from10,001 deliberately seeded metadata-only rows, and holds/restarts without recover/reopen.

[windows-media-file-observation.mjs](windows-media-file-observation.mjs) observes one explicitly supplied offline NTFS key using a bound root identity and a static [native helper](windows-media-file-observation.ps1). It checks final handle paths, links, volume/type, size, timestamps and ancestor state around a bounded SHA256 read. Reparse/offline/case aliases/hardlinks and byte limits stay unsupported; sharing/native failures stay unreadable, and only a missing open beneath a bound root becomes absent. Input/transport is strict, private PowerShell cache directories are retained, and media is never created/deleted/rewritten. Root/region are caller declarations; there is no whole-tree/runtime exclusion/deletion or recovery authority. [Native Windows checks and retained originals](../docs/cycles/evidence/C103/review.md) describe the measured scope and race/remote/production limits.

C103 also retains a controlled pause-only native probe: sharing blocks ordinary writes/renames/new links but allows write-time metadata changes. Before/after metadata comparison must retain changed/uncertain observations with no digest; sharing alone is not a whole-runtime lease. Other filesystems and remote/recall behavior remain unaccepted despite conservative native flags.

[media-delete-intent.mjs](media-delete-intent.mjs) prepares a versioned SQL journal entry containing the authoritative media row and supplied native observation. It supports caller-owned transactions and rejects mismatched keys, size, competing operations and changed-row retries. Prepared means neither logical nor physical deletion. It has no connection owner, endpoint, production migration, durable address reservation or recovery authority. [Current checkpoint](../docs/cycles/C104-media-delete-intent.md) retains actual isolated PostgreSQL proof separately from server/API integration.
