## Audited target contract

The implementation calls the selected owned loopback runtime and production dataset. It never changes global CLI configuration or silently enables writes.

- `POST /v1/plugins/bulldocs/papers/:slug/create` is the native-block insert-only route merged in [PR #20020](https://github.com/FRIKKern/barkpark/pull/20020) at b70214090 (the original C044 audit used30c007e43). Existing published/draft targets refuse. C044 tested three six-caller races and dropped post-commit responses. A concurrent generic draft is not namespace-reserved; final verification still checks ambiguity.
- The older `POST /v1/plugins/bulldocs/papers` route is create-or-replace without an `ifRev` fence. Generic createIfNotExists+publish also overwrote published content in the C044 audit. Neither is a migration retry mechanism.
- Paper `/ops` requires a captured valid revision for guarded editing. Stale revisions return412. A response is not a content comparison; read back the structured blocks and acknowledged revision.
- Existing multipart media upload has no audited idempotency key. C050 records a random owned filename before one POST, searches that exact scoped name, requires a complete single match and verifies MIME/size/path/original bytes. Absent or ambiguous interrupted uploads stop for reconciliation; they are never replayed automatically.
- Quality, registered tags, scope and deduplication can refuse publishing. Supply reviewed metadata; do not bypass those checks or reinterpret every409 as an existing owned Paper.

Runtime bindings, source/backup hashes and existing journal records are checked before requests and again at completion. This is observed validation under caller-provided quiescence, not a cross-service atomic snapshot or power-loss guarantee.

### Actual read contract and limits

Manual-connection providers still request one60-row page. C069 managed-local provider tools use complete published/draft traversal. Foreground `listAllPapers`/`cliListAllPapers` now validate complete bounded traversal with one-identity page overlap; native200/201 proof is accepted in C056. Upstream `QueryController` does support `limit`, `offset`, `hasMore` and `nextOffset` with a 1000-row limit and 100000 offset ceiling. Runtime-validate the envelope, strictly advancing offsets, IDs and completion; a missing nextOffset with hasMore:true is incomplete. Existing upstream tests demonstrate stable traversal on fixed data, but they were only inspected in C055. Offset traversal is not a transaction snapshot: concurrent updates can move rows. Migration must reconcile against the complete pinned source-to-target inventory under a proven writer fence; do not infer completeness from a count or one page.

`getPaper` already asks for raw perspective. In the audited upstream raw read, the exact row wins; only an absent bare row falls back to its draft twin. Draft perspective instead prefers the twin. Do not label raw as newest-draft semantics or silently merge their revision domains. Audit the real managed runtime and authority identity when implementing the catalog; a mutable endpoint is not sufficient ownership.

### Writer and lifecycle limits

Main-process legacy `docs:*` handlers still write legacy documents. C069 routes managed-local API/MCP creation to owned Paper drafts; manual/legacy connections retain their existing creation path. Provider scopes hold actual bound store/document/edit handles; child MCP and goal workers receive those contexts. Profile IPC waits for handlers, not long-running provider processes. Existing runtime leases and legacy-adoption ownership are useful primitives, not a note-engine cutover fence. C075 adds store-owned admission to legacy/Paper/workspace/media writes and propagates captured tokens through API/MCP/goal processes. MCP reads never reseed; initial legacy startup may seed only an open store. Quiescence remains an internal controller and does not establish child teardown, draft recovery or authority selection.

The native create-only route accepts published slugs and applies publishing/label walls. Its existing tests refuse tagless ingestion and wall-failing fresh creation without writing a draft or published row. C044–C054 use reviewed migration metadata; they do not prove that an ordinary blank local note works. C067 separately uses the audited generic draft mutation and exact draft ops for the human journey, preserving those publication rules. C069 extends that draft path to managed-local agents; it does not activate migration.

Other content/media formats remain refused rather than silently flattened. P3 owns cross-machine export/import and database portability; a copy of live database files is not an export contract. G1/G2 remain separate integration gates, not reasons to claim these local contracts complete.
