## What a person can now do

### Let an agent read documents in Barkdown run from source

[#160](https://github.com/FRIKKern/barkdown/pull/160). This is for the dev app: Barkdown run from source with `npm start`, with the library set to the Barkpark CLI, Barkpark's command-line tool. The installed app is unchanged.

1. Start the dev app with `npm start`, with the library set to the Barkpark CLI.
2. Start a chat with Claude Code or Codex.
3. Ask it to look up or read a document. It can.
4. Ask it to edit one. It gets a plain sentence saying it cannot; in the dev app with the CLI library, agents read documents but do not edit them.

## Where it is slow or rough

- In the dev app with the CLI library, agents can read documents but not edit them (#160).
- #160 was not tried in a dev-app session with a real provider and a real CLI library, nor in a live Electron app, nor on Windows locally. Its tests use a stand-in CLI (#160).
- The two nightly runs after #169 merged, at 22:50 on Friday and 04:15 on Saturday, failed. So #167 and #169 wait for a green nightly.

## Across the projects

Barkdown keeps its notes in [Barkpark](https://github.com/FRIKKern/barkpark). In the dev app with the CLI library, an agent's document reads go through Barkdown's main process, which starts the Barkpark CLI for each read and keeps the CLI's 60-second limit (#160).
