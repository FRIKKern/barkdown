## What a person can now do

### Put your words back after a save conflict at quit

[#149](https://github.com/FRIKKern/barkdown/pull/149). A save conflict means the note changed in the library after your tab loaded it, so the library refused your save. If that happens as you quit, Barkdown keeps your words as a retained draft. Now the note tells you so.

1. Open the note again. It shows **Words were not saved**.
2. Press *Put the words back*. Your kept words are written onto the note, in one write checked against the note's current version.
3. If the note has changed since your words were written, the notice says so before you press: "This note has changed since. Putting your words back replaces the newer text; it is kept in Retained drafts." The press keeps that newer text as a retained draft first, and the toast afterwards has a *View retained drafts* button.

- If the newer text cannot be kept, the note is not written, and both texts stay as they are.
- If the note changes while the notice is open, nothing is written. The tab loads the newest text, shows the notice again and waits for another press.
- The notice goes away once you choose: put the words back, dismiss, load the server's version, re-apply your edit on top, discard unsaved edits, or let a later save land. Until you choose, it shows again when you close and reopen the tab, or quit and start again.

### Save as a note: a refusal says why, and nothing blocks the next save

[#147](https://github.com/FRIKKern/barkdown/pull/147). Save as a note, in a chat's menu, writes the chat to a Paper note.

- **Refused**: when the library refuses the note (for example, too large or not valid), or writing is off, the request is dropped at once, and a toast gives the library's reason. Later saves go ahead.
- **Not confirmed**: when Barkdown cannot confirm the note was saved, Pages shows *Chat note not confirmed.* (or *Saved page not confirmed.* for a saved web page) with **Retry**, which checks the same note, and **Discard**, which drops the request so the next save makes a new note. With the library off, Retry says so and keeps the request. Retry opens the note beside the chat it came from.
- **Another chat while one is kept**: Save as a note on a second chat first checks the kept one quietly, then saves the second. If the kept one still fails, the toast names that chat, says the second was not saved, and says what to press; pressing it saves each chat once.
- **Long chats**: a chat note holds at most 524,288 bytes of Markdown. Whole messages go in from the start; a single very long message is cut at a line, with its code block closed; the note ends with "…(cut: N more messages)".
- Today's note (from 18 November) now also drops a request the library refused.

### Chat search opens the message you picked

[#152](https://github.com/FRIKKern/barkdown/pull/152). In quick open's **In chats** group, pick a hit. The chat opens on that message, even when a message above it was deleted or added since you searched. If the message itself was deleted, a toast says *That message was deleted.* and nothing is highlighted.

- Each message now has its own id. Older messages get one the first time their profile loads, and keep it.
- Search keeps copies of your chats in memory, at most 64 MiB across all profiles; the oldest copy goes first, and a profile larger than that is read again on each search. That cap now counts each message and chat, not only their characters ([#156](https://github.com/FRIKKern/barkdown/pull/156)).

### @ mentions send only the notes you picked

[#150](https://github.com/FRIKKern/barkdown/pull/150), [#155](https://github.com/FRIKKern/barkdown/pull/155). In a chat's message box, type @ and pick a note, as on 18 November. What goes with the message now follows what is in the draft:

- Enter on "No note matches" closes the picker and sends nothing.
- A note goes only if you picked it in this draft and its `@[Note title]` is still there. Typed by hand, the same text is plain text and sends no note.
- Select all and delete, then Undo, and the note comes back. Cut the pick and paste it back, and it stays. Paste it into a later draft, and it is plain text.
- Press Up for an earlier message, and it comes back with the notes it named.
- Two notes with the same title: the second pick shows with a number, such as `@[Plan (2)]`, so Undo never sends a note other than the one on screen.
- A note's title reaches the assistant as one plain line: line breaks, tabs and other spacing become one space, and zero-width characters are dropped. Letters, digits, punctuation, symbols and emoji stay.
- The assistant gets a mentioned note's text as that note's text: a line in it that looks like the closing `</note>` marker is changed so it cannot end the note early. Words such as `<notebook>` or `</notes>` are left as typed.

### Import Markdown files

[#148](https://github.com/FRIKKern/barkdown/pull/148). Import Markdown files into the library.

- A link or picture link keeps its address only when it is a web, email or phone link, a link within the page, a relative link, or a link between the imported files. Any other link keeps only its words.
- If the library does not allow Barkdown to write, the import stops at the first note with one message: "Barkdown is not allowed to write notes here: … Nothing more was imported." No note is marked as refused, so once writing is allowed, the same files import in full.
- If a file was held because the library was busy or out of reach, and you edit it before importing again, its new text comes in as that same note.
- Code between ``` fences or in a code span is stored exactly as written; links in it are not rewritten, and a picture written inside code is not uploaded. A code line that looks like a heading is never taken as the note's title.

## Where it is slow or rough

- None of these fixes was run locally on Windows (#147, #148, #149, #150, #152, #155, #156). The nightly is for Mac only.
- The Desktop suite on macOS and Linux runs weekly and on request only, so on pull requests chat search's live test runs on Windows alone (#157).
- A real library refusal of a saved chat, including a too-large one, was not tried end to end; the tests forced it (#147).
- Two live tests of moving older notes to Paper notes fail on main, as they did before #148; neither runs in the hosted checks (#148).
- After a profile load while the library is preparing to change engines, search skips older messages without an id until the next normal load (#152).
- A message can wait about 4.5 seconds when a mentioned note is open with unsaved edits (#150).

## Across the projects

Barkdown keeps its notes in [Barkpark](https://github.com/FRIKKern/barkpark). Paper notes, chat notes and imported files are Barkpark documents. The import's link rule is Barkdown's copy of the rule Barkpark's reader uses for links, and its tests use Barkpark's own test cases word for word (#148). A refused chat note shows the reason code the Barkpark library sent back (#147). Putting words back is a write checked against the note's current version in the library (#149).
