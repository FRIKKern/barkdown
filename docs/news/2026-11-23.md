# Barkdown · Monday 23 November 2026

One pull request merged ([#177](https://github.com/FRIKKern/barkdown/pull/177)). It changes what an assistant in a Barkdown chat may do without asking. The Mac nightly `0.6.0-nightly.20261123.1`, published at 05:16 on Monday 23 November, was built from main at this merge, so it is in a downloadable build. The nightly is a pre-release for Apple silicon and Intel, on the [releases page](https://github.com/FRIKKern/barkdown/releases).

## What a person can now do

### Choose how far an assistant may go

Barkdown had a separate switch, called Full YOLO, that let an assistant run Barkdown's administrative commands. It is now part of one choice.

1. Open a chat. Under the composer, the chip reads **No approvals**, the default. The same choice is in Settings › Assistant.
2. With **No approvals**, an assistant can run Barkdown commands for you, now including changing settings, managing profiles and deleting items, with no second switch.
3. Click the chip for **Ask first**. Barkdown's approval prompts come back, and settings, profile changes and deletions are kept for you. An assistant that tries one is refused and is told to say why.
4. Changing the approval mode, quitting and restarting always stay with you; an assistant cannot do them in either mode.
5. Each profile keeps its own choice. A run still going in the background keeps its own profile's mode when you switch profiles in the window.

Codex tool permissions and browser pauses follow their own rules, as the chip's tooltip says. A Codex path set by an assistant through `settings.set providerBinary.codex` must be an absolute path, as in the Settings field.

## Where it is slow or rough

- The default is the open one: an assistant can change settings and delete items unless you pick Ask first (#177).
- On the installed nightly, a live chat used the Codex CLI that ships with ChatGPT, `0.167.0-alpha.3.2`, an alpha build (#177).

## Across the projects

Barkdown keeps its notes in [Barkpark](https://github.com/FRIKKern/barkpark). Three of #177's runner checks need a Paper, Barkpark's document type, and passed with a throwaway library (#177). Barkpark itself spent Monday on Papers too: a `bp paper pull` now prints every level of a nested list, and a push stores every level ([FRIKKern/barkpark#28384](https://github.com/FRIKKern/barkpark/pull/28384)).
