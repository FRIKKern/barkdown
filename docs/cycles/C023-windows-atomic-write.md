### Support and retained-chain recovery limits

Verified on this Windows C: NTFS volume. Managed writeJson now requires exclusive same-volume hardlink support; unsupported linking refuses without changing the target or publishing an empty owner. No network filesystem, rogue-writer compare-and-swap, PID-reuse availability, directory fsync or power-loss guarantee. Existing default lease callers retain their earlier behavior.

Malformed owner metadata or a chain beyond8 recovery levels is deliberately not auto-repaired. Tests preserve every chain byte and authoritative workspace. On that error, stop further writes and retain the workspace, all lease/recovery/abandoned/private-owner files and process evidence. An operator must establish that every potential writer is stopped and inspect the complete chain before an explicitly reviewed recovery; this cycle supplies no automatic chain cleanup or repair UI. A live or unidentifiable owner must not be removed based on elapsed time, empty bytes or guessed PID. Ordinary tested single/crash recovery remains usable; repeated crashes exceeding the bound remain an explicit recovery limitation.
