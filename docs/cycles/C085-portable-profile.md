# C085 — Portable profile

**Status:** active, opened 2026-09-29. Stage P3 groundwork, started while P2's remaining exits (a real library, the Windows return checkpoint) wait for the Windows machine ([D-cycle-order](../DESIGN-DECISIONS.md#d-cycle-order--p3-groundwork-starts-while-p2-waits-for-windows-2026-09-29)).

**Outcome so far:** a person can export a profile and import it as a new one from Settings, without a terminal, and open the imported profile.

**Export (`app/main/profile-export.js`, `e7db315b`, `2ee80c97`):** on a prepared profile, under a read-only runtime lease and the upstream hold, the runtime driver takes a custom-format `pg_dump` of its own database, the owned media directory and the profile's files are copied, and a manifest records every file's size and hash, the hold's seal, the Barkpark version, the Paper count and the navigation owner. Credentials, the owner key, ports, fences and caches stay behind and the manifest says so; settings travel without their encrypted fields. A folder is never overwritten and the runtime is reopened whatever happens. Rehearsed against a real runtime: a write in the middle of the export is refused with 503, the export verifies, and the dump restores into a scratch database with the same Papers ([result](evidence/C085/live/2026-09-29T11-44-58-403Z-export/result.json)).

**Import (`app/main/profile-import.js`, `2ee80c97`):** the export is verified and must come from the same Barkpark version; a new profile is created; the pool allocates its descriptor and credentials the ordinary way; the driver restores the dump and the media into a private cluster that has never booted and removes the exporter's token rows, so the first boot seeds the importing runtime's own token; the profile's files are copied with the exported profile id and navigation owner rewritten for the importing library, while retained originals and rollback evidence are copied verbatim. A journal names the phase. Rehearsed between two real runtimes in one registry: the imported profile boots and serves the same Papers, revisions, blocks and image bytes, refuses the exporting runtime's token, accepts an edit that leaves the exported library unchanged, and its Pages, favorite, tab, conversation and draft arrive owned by the importing library ([result](evidence/C085/live/2026-09-29T12-03-39-481Z-import/result.json)).

**From the app (`app/main/profile-portable.js`, `8e3a01b2`):** Settings, General, Storage has Export and Import. The folder comes from the native picker in the main process and is held there. Export prepares the profile, says its phases in the notice, releases the preparation when it ends either way and records the outcome against that preparation; the notice names the counts and the folder and offers Restart. A failed export moves its partial folder to the system trash. Import creates the new profile and selects it in the profile list; Switch opens it. The manifest now counts draft-only notes beside published Papers, because a note written in the app is a draft. [Electron rehearsal](evidence/C085/live/2026-09-29T12-53-15-409Z-portable-ui/result.json): six checks, including the imported profile's Pages owned by the importing library, its conversation with the unsent draft, a retained original, and an assistant edit with Undo.

**A host that dies (`app/main/runtime-orphan.js`, `af8fd17d`):** a managed runtime and its database outlive a Barkdown that is killed, and the next launch used to stop at "Port already in use". Each launch is now recorded (host, runtime process, both start times); the next start stops the leftover when the record proves it is this profile's own, and refuses when the recorded host still runs. [Rehearsal](evidence/C085/live/2026-09-29T13-28-46-130Z-runtime-reclaim/result.json): kill, relaunch, same library, writing works, a clean quit leaves nothing.

**Interruption (`e0621d07`):** the export journals before the hold. After a kill in the middle, the notice names the interrupted export and offers one action: Discard recovers the runtime (it comes back in recovery after a kill while held), moves the partial folder to the trash and releases the preparation; the export is then taken again. A folder that verifies is kept as complete. An import that did not finish is listed in Settings, cannot be selected, and is imported again from the folder its journal names, or discarded; a failing import is discarded at once. [Rehearsal](evidence/C085/live/2026-09-29T13-30-41-952Z-portable-interrupt/result.json): five checks with real kills.

**Refusals (`614b4c7d`):** a tampered, a truncated, an added-to and an other-version export, and a folder that is not an export, are each refused from Settings with a plain reason and create no profile and no folder; an export folder that a person opened in a file manager still imports. A completed outcome notice is dismissed once. [Rehearsal](evidence/C085/live/2026-09-29T13-53-17-297Z-portable-ui/result.json): seven checks.

**A library that refuses changes (`2961aa4e`, carried from C083):** a runtime whose host was killed while it was held comes back in recovery and refuses every writer; nothing in the app could reopen it. Now the operations that reconcile by their own journal (switch, rollback, comparison, export) recover it before they hold, and a launch that finds it in recovery with no operation in flight reopens it. [Rehearsal](evidence/C085/live/2026-09-29T14-42-36-398Z-runtime-recovery/result.json): a kill while held by nobody, and the library switch killed after its journal reached `replacing`, resumed from the notice to a writable library on Paper with each note once. The same rehearsal exposed that any failed write left an uncertain entry in the writer journal that blocked every later preparation, for good. A write the server answered is now settled, a departed host's runtime writes are settled once this host has started the runtime anew, and a note refused at the door of a held library can be sent again. A stopped preparation says why in the notice.

**A writer whose connection is cut ([rehearsal](evidence/C085/live/2026-09-29T14-03-05-371Z-dying-writer/result.json)):** an admitted write of 800 mutations had its connection cut while a hold drained. The runtime finished the write and reached the hold; nothing died. A writer that raises inside the runtime during a drain is therefore not produced from outside, and is covered upstream by the coordinator's own tests.

**Decisions:** [D-writer-settled](../DESIGN-DECISIONS.md#d-writer-settled--an-answered-write-is-settled-2026-09-29), [D-runtime-recover](../DESIGN-DECISIONS.md#d-runtime-recover--who-reopens-a-runtime-in-recovery-2026-09-29), [D-portable-interrupt](../DESIGN-DECISIONS.md#d-portable-interrupt--nothing-resumes-a-half-written-export-or-import-2026-09-29), [D-runtime-reclaim](../DESIGN-DECISIONS.md#d-runtime-reclaim--a-leftover-runtime-is-stopped-only-on-proof-2026-09-29), [D-portable-app](../DESIGN-DECISIONS.md#d-portable-app--export-and-import-as-settings-actions-2026-09-29), [D-portable-export](../DESIGN-DECISIONS.md#d-portable-export--what-travels-in-a-profile-export-and-what-never-does-2026-09-29).

**Limits:** one machine, one Postgres major version, a small library; both profiles in one registry. Import needs the same Barkpark version as the export. Rollback of a switch is not offered on an imported profile (its retained workspace names the exported profile). Interruption is rehearsed at one stall point per operation, with SIGKILL. The native folder picker and the system trash are stubbed in the app rehearsals. The Windows reclaim path is not rehearsed. While an interrupted export stands, the sidebar shows no pages until it is discarded. An export ends with a restart, because the process that released a preparation does not edit again.

**Carried from C083:** the Windows return checkpoint and a real library (Windows machine back about 2026-10-05); whether pre-existing cloud references get the managed owner at projection; a retention rule for committed visual runs. Recovery is delivered above.

**Observed, not chased:** one drag step of the sidebar journey (`tests/run.mjs`) failed once in a full unit run and passed twice alone.

**Next action:** the second machine when the Windows machine is back: an export taken on one machine imported on the other, the reclaim path on Windows, the return checkpoint and a real library. Until then, groundwork that does not depend on Windows.
