# Static file aliases in profile exports

The earlier directory-root repair did not inspect top-level workspace/settings files or hard links. [Eight disposable probes](export-file-alias-characterization.json), using the [original harness](export-file-alias-probe-before.mjs), show four hard-linked paths and two top-level file symlinks copied an outside-profile sentinel into a verified export. Nested attachment/media file symlinks already refused. All files were created inside owned temporary fixtures; no real content was read or changed.

Eight real hard-link regressions [fail before](export-file-alias-before-01/result.json) and [pass after](export-file-alias-after-01/result.json): workspace, settings, attachments and media sources; archive manifest, database, workspace and media payloads. Refusal preserves outside bytes, advertises no completed export and releases the operation's hold/lease. Archive verification refuses even when payload bytes and hashes match.

The repair checks lstat before copied source files, settings reads and listed archive payload reads. Symbolic links and files with more than one hard-link name refuse; nonregular files also refuse. Missing optional source files remain optional, but dangling links are not mistaken for absence. The manifest receives the same check before parsing. This deliberately refuses multiple hard-link names even when both happen to be inside the profile: the exporter cannot establish that all names belong to this library. Excluded machine files remain excluded.

[Real Windows hard-link and file-symlink proof](export-file-alias-final-01/result.json) now refuses all eight constructed aliases in200ms. The [after receipt](export-file-alias-characterization-after.json) includes exact implementation SHA-256; the original receipt/harness and failing tests remain retained. Adjacent export/import/portable and host-skip checks pass3.017s. Native logical export, current screenshots and root verification are the next gates in the active handoff.

Scope is static file aliases, alongside the prior static directory-link refusal. This does not prevent filesystem substitution between checks and reads, identify every ancestor alias, prove historical media reconciliation or certify a real Mac transfer. It does not add an inventory endpoint or change the pinned runtime. Existing source/runtime ownership and admission checks remain required.
